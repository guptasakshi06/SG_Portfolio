## Implementation and maintenance

Files: `src/features/search/{search.ts,CommandPalette.tsx}`, `src/styles/search.css`, shared `AppShell.tsx`/`TopBar.tsx`, `tests/search.test.ts`, README and HANDOFF. No new content facts or route components.

The index is built once at module scope from explicit typed public fields. Projects use existing overview/category fields and source-attributed technology names. Skills reuse `skillHref(id)`. Portfolio results use existing heading anchors. Page summaries and content snippets derive from JSON rather than duplicate biographies. No notebooks/experiment fixtures/private configuration are serialized into the search index. Future additions to the indexed collections appear automatically; adding another field is an intentional allowlist edit.

Native dialog mounts only while open and makes the background inert. Cleanup closes it, restores body overflow and returns focus on dismissal. Up/Down/Enter use the active option; pointer/touch click uses the same navigation callback. AppShell handles destination focus after dialog cleanup, including query-only skill changes and anchored content. Ordinary catalog query typing and skill selection retain their prior focus behavior. Location-key state is cleared conditionally on a route change so returning through browser history cannot resurrect search.

React quality checklist applied: small typed feature components; pure matching/navigation helpers; one derived result set, stable record IDs and no extra state library; global listener cleanup; dialog and body cleanup; no HTML injection; input composition guard; native editing keys; explicit ARIA semantics and focus visibility; no animation or heavy library. Existing lazy chart/notebook code is preserved. Official references: [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), [native dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).
