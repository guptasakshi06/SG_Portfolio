# S10 — Contact, resume states, and SEO

Date: 2026-11-04, Asia/Kolkata. Local-only sprint; no deployment or push. Owner subsequently requested a local S10 commit, recorded in HANDOFF.md.

## Result and boundaries

Contact replaces the final foundation preview with editable JSON copy, owner-confirmed availability, selectable email, a real encoded mailto, safe GitHub/LinkedIn actions, PDF reader/download and a working Projects next step. No form or submission success is simulated. All eight main pages are implemented.

Topbar, hero, footer email, Contact and palette reuse ProfileAction and the same pure destination resolver. The palette adds email/download quick actions and retains keyboard focus containment. Null inputs are supported; invalid URLs fail content validation and are rejected defensively by the resolver. HTTPS validation now also rejects control/space characters that URL parsing could normalize. Unavailable labels have no href, tab stop, underline or hover interaction.

ResumeProvider shares one same-origin versioned PDF check per app mount. HTTP status, application/pdf MIME and `%PDF-` header are required; redirects/network errors/abort are rejected. A ten-second abort prevents indefinite checking. App cleanup aborts and ignores disposed results. Contact exposes a reader link (new tab, no download) and a download link only when available; checking/missing states have one noninteractive label. Reload retries a transient failure. This is a session availability check and PDF signature check, not a complete parser or continuous monitoring service.

The original owner PDF remains unchanged: 166,684 bytes, one page, SHA-256 `0eeadf37c6a1fb4315648b10ebc5d2e02406425eaf04d5755c62c27cbc65204c`. Website degree remains owner-confirmed Information Technology. The older PDF degree discrepancy stays private maintenance context.

## Metadata implementation

`src/content/seo.json` contains page metadata and nullable productionOrigin. Project metadata derives from actual project titles/summaries. Initial HTML is generated for all eight pages and ten project routes using the Vite HTML transform and the post-build script; runtime navigation replaces the same managed tags without duplicate descriptions. Page components no longer declare competing titles. The unused FoundationPage/notice was removed.

This is static **head metadata**, not full-page prerendering. Bodies require JavaScript. Hosts must serve each generated route index before applying the general SPA fallback; real hosting/rewrite verification remains S12. No crawler/indexing or social cache guarantee is claimed.

Production origin is null: no canonical, og:url, absolute OG/Twitter image URLs, robots.txt or sitemap.xml; initial/client metadata uses noindex/nofollow. Once a real origin is configured, the same code derives all absolute addresses and crawl files. Origin-enabled output is tested with isolated test inputs, not deployed. The original SG 1200×630 PNG resolves; its editable SVG is preserved. Both are original typography/grid/orbit artwork with no metrics or invented portrait.

Official reference checked: [Vite HTML transform API](https://vite.dev/guide/api-plugin#transformindexhtml). README documents metadata-only limitations, source editing, cache/version behavior, owner-content intake and hosting prerequisites. The React checklist was applied: small typed components, stable status context, one cleanup-aware PDF effect, no unnecessary state library/dependency, native links/dialog behavior, visible focus, keyboard operation and preserved lazy chart/notebook chunks.
